\subsection{Preflight Gate}

\subsection{Provider-Compatible Invocation}

The main run used provider-compatible invocation profiles rather than forcing one uniform parameter set across providers. This matters because fixed caps produced empty outputs for \code{deepseek-v4-pro} and \code{kimi-k2.6} during preflight or budget audit. A later no-cap diagnostic showed that the empty-content failures were consistent with token-cap/profile incompatibility rather than unavailable upstream models.

The no-cap settings did not inflate visible output in the main run. DeepSeek averaged 399.825 visible output tokens, Kimi averaged 404.205, and both had \code{overlength_rate=0.0}. Across the main run, \code{empty_output=0/1000}; DeepSeek had one schema-missing row and all other models had full parse success.
